MISE EN LIGNE DU SITE 1LIFE PRODUCTION — ÉTAPES
================================================
(Vercel + Resend + domaine OVH) — compter ~1 h, hors délais DNS.
Le dépôt est prêt : build "npm run build", toutes les pages pré-rendues,
formulaire via /api/contact (Resend). Rien à changer dans le code.


ÉTAPE 1 — COMPTE GITHUB DU CLIENT ET TRANSFERT DU DÉPÔT (15 min)
----------------------------------------------------------------
1. Le client crée un compte GitHub (idéalement avec une adresse générique,
   ex. tech@1lifeproduction.fr) : https://github.com → Sign up.
2. Transfert : sur https://github.com/seg1-exe/1lifeproduction
   → Settings → tout en bas "Danger Zone" → "Transfer ownership"
   → saisir le nom d'utilisateur GitHub du client.
   Il reçoit un e-mail à accepter (valable 24 h).
3. Une fois transféré, le client va dans Settings → Collaborators
   → "Add people" et ajoute Arthur avec le rôle Admin (pour continuer à pousser).
4. Sur le poste d'Arthur, mettre à jour l'adresse du dépôt :
       git remote set-url origin https://github.com/LEUR-COMPTE/1lifeproduction.git

   Alternative si le client ne veut pas de compte GitHub : garder le dépôt
   sur seg1-exe et ne faire que l'étape 2 avec ce compte. Moins propre,
   mais fonctionnel.


ÉTAPE 2 — COMPTE VERCEL ET PREMIER DÉPLOIEMENT (10 min)
--------------------------------------------------------
1. Le client va sur https://vercel.com → Sign Up → "Continue with GitHub"
   (avec le compte de l'étape 1).
   Plan Hobby (gratuit) pour commencer ; passer en Pro (20 $/mois) si Vercel
   le demande (les CGU Hobby excluent l'usage commercial).
2. "Add New → Project" → importer 1lifeproduction.
   Vercel détecte Nuxt tout seul : Framework "Nuxt.js", Build Command
   "npm run build", Output automatique. NE RIEN CHANGER.
3. Environment Variables (avant Deploy, ou après dans Settings →
   Environment Variables puis "Redeploy") :

       RESEND_API_KEY   = la clé de l'étape 3 (mettre "re_test" provisoirement)
       RESEND_FROM      = 1LIFE PRODUCTION <noreply@1lifeproduction.fr>
       RESEND_TO        = contact@1lifeproduction.fr

4. "Deploy". Au bout de ~2 min le site est en ligne sur
   https://1lifeproduction.vercel.app
   Tout fonctionne sauf l'envoi d'e-mail (étape 3).


ÉTAPE 3 — RESEND : CLÉ API ET DOMAINE (15 min + attente DNS)
-------------------------------------------------------------
1. Créer un compte sur https://resend.com (même adresse générique).
   Gratuit : 3 000 e-mails / mois, largement suffisant.
2. API Keys → "Create API Key" → nom "site-1life", permission "Sending access"
   → copier la clé (re_…), elle ne sera plus affichée.
   La coller dans Vercel (RESEND_API_KEY) → Redeploy.
3. Domains → "Add Domain" → 1lifeproduction.fr, région "Europe (Ireland)".
   Resend affiche 3 enregistrements DNS à ajouter chez OVH :
       - TXT sur resend._domainkey   (DKIM)
       - MX  sur send (ou bounces)
       - TXT sur send                (SPF : v=spf1 include:amazonses.com ~all)
4. Chez OVH : Noms de domaine → 1lifeproduction.fr → Zone DNS
   → "Ajouter une entrée", recopier les 3 à l'identique.
   ATTENTION : OVH ajoute parfois ".1lifeproduction.fr" tout seul au
   sous-domaine — ne pas le doubler.
5. Retour sur Resend → "Verify". Vert en général sous 30 min (jusqu'à 24 h).
   Tant que ce n'est pas vérifié, les envois sont refusés : c'est normal.
6. Test : remplir le formulaire sur 1lifeproduction.vercel.app
   → l'e-mail doit arriver sur contact@1lifeproduction.fr
   (vérifier les spams la première fois).


ÉTAPE 4 — BRANCHER LE DOMAINE SUR VERCEL (10 min + attente DNS)
----------------------------------------------------------------
Le domaine 1lifeproduction.fr est chez OVH et sa zone DNS est bien gérée
par OVH (serveurs ns103/dns103.ovh.net) : c'est là qu'on édite.
La zone contient aussi les MX d'OVH (mx1/2/3.mail.ovh.net) et un SPF
"include:mx.ovh.com" : NE PAS Y TOUCHER (boîtes mail du domaine).

1. Vercel → projet → Settings → Domains → Add :
   1lifeproduction.fr, puis www.1lifeproduction.fr
   (Vercel propose de rediriger www vers la racine : accepter).
   Vercel affiche alors les valeurs exactes à utiliser (A pour la racine,
   CNAME pour www). Utiliser CELLES-LÀ.
2. Zone DNS OVH (Noms de domaine → 1lifeproduction.fr → Zone DNS) :
       - sur la racine "@" (sous-domaine vide) : MODIFIER l'enregistrement A
         145.239.37.162 (page d'attente OVH) → 216.198.79.1 (valeur Vercel
         en 2026 ; 76.76.21.21 fonctionne aussi). Un seul A sur la racine.
       - sur "www" : SUPPRIMER les A / AAAA existants et mettre un CNAME
         vers la valeur affichée par Vercel (du type xxxx.vercel-dns-0xx.com,
         ou cname.vercel-dns.com), avec le point final si OVH le demande.
       - laisser MX, SPF (TXT racine) et les autres entrées en place.
   Piège : OVH ajoute lui-même ".1lifeproduction.fr" : dans le champ
   sous-domaine, saisir "www" (pas "www.1lifeproduction.fr") et rien
   pour la racine.
3. Attendre que Vercel passe les deux domaines en "Valid Configuration"
   (TTL actuel 1 h : compter jusqu'à 1 h après la modification).
   Le certificat HTTPS est automatique.
4. Vérifier https://1lifeproduction.fr : site, formulaire, /sitemap.xml,
   et les redirections /a-propos → /equipe et /commercial → /marque.


ÉTAPE 5 — SORTIR LE PROJET DU COMPTE D'ARTHUR
----------------------------------------------
Une fois le domaine actif sur le projet du client :
Vercel d'Arthur → ancien projet → Settings → "Delete Project".
Si l'ancien projet portait le domaine, le retirer d'abord de ses Domains
(sinon Vercel refuse de l'ajouter au nouveau projet).


ENSUITE, EN CONTINU
-------------------
- Chaque "git push" sur main redéploie automatiquement en ~2 min.
- Les clés ne sont JAMAIS dans le code : uniquement dans Vercel.
  Le fichier .env.example sert de modèle pour travailler en local.
- Mise à jour du contenu : voir GESTION-CONTENU.md.


POINTS À ANTICIPER
------------------
- 1lifeproduction.COM n'appartient pas au client (un autre site y répond) :
  tout le site, le sitemap, les mentions légales et les e-mails sont sur
  1lifeproduction.FR.
- L'adresse d'expédition noreply@1lifeproduction.fr n'a pas besoin
  d'exister comme boîte mail (c'est le domaine vérifié qui compte).
  Les réponses des visiteurs arrivent bien à contact@1lifeproduction.fr :
  le formulaire met l'e-mail du visiteur en "Reply-To".
- Les mentions légales indiquent Vercel Inc. comme hébergeur : si le site
  est déplacé un jour, mettre à jour content/legal.json.
